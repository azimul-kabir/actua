# Actua 1.0.0-beta.15

This quick beta hotfix improves the final step of OpenID Connect authentication introduced in beta.14.

## Fix

- **Returns to Actua automatically.** After the Actual server completes browser-based OIDC authentication and Actua captures the session, the browser now redirects directly back to the existing Actua connection screen.
- **No misleading expired interaction page.** Users should no longer remain in the browser on a stale or expired OIDC interaction message after authentication has already succeeded.
- **Manual fallback included.** If a browser does not open Actua automatically, the callback page includes a **Return to Actua** link.

## Security

The Actual session token is received only by Actua's temporary localhost listener. The app deep link contains no token, credentials, identity-provider secrets or budget data. The listener remains bound to the device loopback interface and closes when the sign-in attempt finishes.

## Upgrade notes

Actua 1.0.0-beta.15 uses the same production application ID and persistent release signing identity as beta.14, so it should install as a normal in-place update. Obtainium users who enabled prereleases should receive the update after publication.

> [!CAUTION]
> Actua remains beta software and can write synchronized changes back to an
> Actual budget. Create an independent backup of an important Actual budget
> before testing, and confirm important changes have synchronized before
> uninstalling or resetting Actua.

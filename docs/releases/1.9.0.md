# Actua 1.9.0

Actua 1.9.0 redesigns Reports. Every chart is smoother and easier to read, almost every bar, point,
slice, node and day opens the transactions behind it, and each card has a full-screen view with a
time range and a data table. The rule editor can now add split actions, and pop-up messages use the
app's own style.

## Before you update

- **Reports look and behave differently.** Charts have axes and month labels, tooltips show the real
  value at each point, and tapping a bar, slice or day opens its transactions. Figures are unchanged;
  see "Compatibility and safety".
- **Calendar reports swipe between months.** Long-press a day for its income and expense by category.
- As always, let Actua finish syncing before you update, and keep an independent backup from
  Actual before using a new version with a real budget.

## Added

### Reports

- A drill-down transactions sheet with the period, count and total, search, sorting, tap-to-edit and Open in Transactions ([#1125](https://github.com/azimul-kabir/actua/pull/1125))
- Tapping an Income/Expense or Cash Flow bar opens that month's transactions ([#1128](https://github.com/azimul-kabir/actua/pull/1128))
- Net Worth, Age of Money, Balance Forecast and Crossover use smooth line charts with value and month labels and a drag tooltip; Net Worth months open their transactions ([#1129](https://github.com/azimul-kabir/actua/pull/1129))
- Donut reports gain slice gaps, one-tap slice drill-down, long-press focus and an "Other" slice for more than 12 categories ([#1132](https://github.com/azimul-kabir/actua/pull/1132))
- Calendar reports gain month swipe, per-day bars with today highlighted and a long-press category breakdown ([#1133](https://github.com/azimul-kabir/actua/pull/1133))
- Sankey reports draw names and shares inside the bars; tapping a node or flow opens its transactions ([#1134](https://github.com/azimul-kabir/actua/pull/1134))
- Budget Analysis shows budgeted, spent and overspending bars with a balance line, and Monte Carlo shows shaded outcome ranges around the median ([#1135](https://github.com/azimul-kabir/actua/pull/1135))
- Each report card opens full screen with a larger chart, a view-only time range and a data table ([#1136](https://github.com/azimul-kabir/actua/pull/1136))

### Rules

- The rule editor can create and edit split actions with fixed, percent or remainder amounts ([#1122](https://github.com/azimul-kabir/actua/pull/1122))

## Changed

- Reports dashboard widgets move their title and headline metrics into unified card headers ([#1126](https://github.com/azimul-kabir/actua/pull/1126))
- Reports animate in (unless system animations are off), use one green/red colour language across cards, and read better with TalkBack and at large font sizes ([#1137](https://github.com/azimul-kabir/actua/pull/1137))
- Pop-up messages such as "No network" and "Merged transactions" use the app's own colours and rounded style instead of a black bar ([#1139](https://github.com/azimul-kabir/actua/pull/1139))

## Fixed

- Tapping a day in the Calendar report opens its transactions directly instead of only selecting it ([#1123](https://github.com/azimul-kabir/actua/pull/1123))
- Line chart axis labels show whole units and month labels no longer overlap ([#1131](https://github.com/azimul-kabir/actua/pull/1131))
- The Budget overview card lines up To budget with Budgeted, Spent and Balance ([#1141](https://github.com/azimul-kabir/actua/pull/1141))

## Compatibility and safety

- Report figures are unchanged. Budget Analysis points gain an overspending amount (Actual's
  `overspendingAdjustment`) and Monte Carlo points gain 10th to 90th percentile values; the existing
  median, 10th percentile and success rate are identical for the same inputs.
- Drilling into a chart reads your local budget with parameterized queries; nothing is written.
  The full-screen time range is applied in memory for that view only and is never saved to the
  Actual dashboard widget.
- Split actions in the rule editor use Actual's stored rule format, so rules stay compatible with
  Actual.
- No database schema, encryption, Merkle or sync-protocol changes.

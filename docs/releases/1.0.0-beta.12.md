# Actua 1.0.0-beta.12

This beta focuses on safer recovery, preview-first budget automation, and data-integrity hardening.

## Highlights

- **Import exported backups.** Open **More → Connection & Data → Backups → Import backup** to choose an Actua ZIP archive with Android's system document picker. Actua validates the archive, metadata, Actual database, size, and entry safety before adding it to the managed backup list.
- **Import does not restore.** Choosing a file does not replace the active budget. The imported archive appears in **Available backups** and requires a separate restore confirmation. The active version is still preserved for one-tap revert before restore.
- **Whole-budget target preview.** **Budget → Add → Apply budget template** now previews supported category-target changes before writing anything. It shows current and proposed amounts, the net budget effect, targets already up to date, and categories using unsupported advanced automations.
- **Atomic target application.** Confirmed target changes are written through one Actual-compatible CRDT batch. Actua rejects the application if an involved budget cell changed after the preview, and repeating an already-applied plan makes no new writes.
- **Safer entity management.** Category and category-group deletion, ordinary-payee deletion and merge, and category/group reordering use synchronized Actual-compatible mutations with transfer-payee and historical-reference protections.
- **Compatibility hardening.** CI now covers representative Android 9 and Android 17 behavior, supported SQLite paths, and expanded transfer, split, reconciliation, archive, and mutation integrity cases.

## Current automation boundary

Whole-budget application currently evaluates the target types Actua already edits: monthly spending, fixed monthly saving, save-by-date, refill-to-cap, weekly spending, and recent-month averages. Schedule funding, percentage-of-income, remainder allocation, long-term goal-only rows, notes-managed templates, and cleanup source/sink groups are identified but not executed. Their stored definitions remain unchanged while issue #56 continues in reviewable stages.

## Upgrade notes

Actua 1.0.0-beta.12 uses the same production application ID and persistent release signing identity as recent beta releases, so it should install as a normal in-place update over beta.11. Obtainium users who enabled prereleases should receive the update after publication.

> [!CAUTION]
> Actua remains beta software and can write synchronized changes back to an Actual budget. Create an independent backup of an important Actual budget before testing, and confirm important changes have synchronized before uninstalling or resetting Actua.

# Actua 1.0.0-beta.31

Beta 31 adds support for connecting to servers behind an auth proxy via custom
HTTP headers and lets an account's type be set or changed, plus a round of
performance fixes found by a dedicated audit: eliminated recomposition
hotspots in Transactions/Budget/Accounts/Add Transaction, faster Budget list
scrolling, a batched notes query that removes a per-category/account N+1, and
a baseline profile shipped in release builds for faster startup.

## Added

- Added support for custom HTTP headers (e.g. `CF-Access-Client-Id`/`Secret`) sent with every request to the Actual server, configurable from the Connection screen for servers behind an auth proxy like Cloudflare Access
- Added a type picker to the new-account dialog and a "Change account type" action to the account menu; every account previously showed as "Checking" regardless of its actual type
- Release builds now ship an AOT-compiled baseline profile covering startup, tab switching, and core Budget/Accounts/Transactions scroll paths, reducing reliance on JIT warm-up

## Fixed

- Fixed the Transactions search/filter list and its date-grouping, Budget's category-visibility filtering and a category's recent-transactions list, Accounts' section filtering and per-row credit-card lookups, and the Add/Edit Transaction payee/category/account picker all recomputing on every recomposition (e.g. every keystroke or row-selection tap) instead of only when the underlying data actually changes
- Fixed the Budget list re-diffing incompatible row layouts while scrolling between income/Plan/Table sections, reallocating a copy of each group on every header recomposition, and animating the whole Table-view sticky header instead of just the totals row that resizes; money amounts no longer construct a new number formatter on every render
- Fixed loading a budget month's or the accounts list's notes with one synchronous database round-trip per category/account (plus a repeated table-existence check on each one) instead of a single batched query

## Compatibility and safety

- Custom HTTP headers are sent on every request to the configured Actual server; the field is optional and empty by default, so existing connections are unaffected
- Account type is already a plain field on the `accounts` CRDT table; this only removes the local write-time restriction that hardcoded it to `checking` and allows `type` in the mutation allowlist — it does not change any other account behavior
- Every recomposition/list/query fix changes only *when* or how many times an existing computation runs, or batches previously-separate queries into one; none change a computed value, and each was verified against the existing test suite (`DemoBudgetTest` for the batched-notes query; no other stored/synced data or behavior changed). Actual baseline-profile numbers still require a real device run rather than emulator measurements — see `docs/PERFORMANCE_BASELINE.md`
- See `docs/RECOMPOSITION_AUDIT.md` and `docs/BUDGET_LIST_PERFORMANCE.md` for the full per-screen audit, including two lower-priority spots intentionally left as-is, and `docs/MUTATION_ARCHITECTURE_AUDIT.md` for why `mutate()`'s synchronous main-thread writes were audited but left unchanged pending their own follow-up

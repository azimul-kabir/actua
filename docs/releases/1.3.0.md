# Actua 1.3.0

Actua 1.3.0 is a sync and data-safety release. It reworks how Actua talks to
the Actual server, stores budgets and writes backups so that budgets stay
readable by Actual: bank links, backups and budgets from older Actual versions
no longer get rejected by Actual, downloaded budgets keep unsynced changes,
expired sessions can sign in again, and sync errors that need you to act now
say what to do. Closing an account now follows Actual's flow, and credit card
statements, reminders and the card picker got a round of fixes.

## Before you update

Most of this release changes backend behavior rather than screens. Nothing
here should require action for most people, but please read this first:

- **Sync first and keep a backup.** Let Actua finish syncing before you
  update, and keep an independent backup from Actual (web or desktop) before
  using the new version with a real budget.
- **Budgets where Actua 1.0.0–1.2.0 linked a bank account.** If one of those
  versions linked or unlinked a bank account (GoCardless or SimpleFIN) in a
  budget you *also* use in Actual, Actual may show "Update required: We
  couldn't apply changes from the server…" on every sync and stop receiving
  changes from other devices. Updating Actua stops new bad changes, but it
  can't remove the ones already on the server. Follow the
  [recovery steps](https://github.com/azimul-kabir/actua/blob/main/docs/ACCOUNTS_PARITY.md#recovery-for-budgets-linked-by-actua-v100v120):
  in short, compare recent activity, use *Settings → Advanced → Reset sync* in
  the Actual client with the most complete data, re-download the budget in
  Actua, and relink GoCardless accounts in Manage → Bank Sync. Budgets used
  only in Actua are not affected.
- **Moving to a new phone.** The server connection, custom HTTP headers
  (for example Cloudflare Access secrets), budget encryption passwords and
  trusted server certificates are no longer copied by Android's
  device-to-device transfer or cloud backup. On a new phone, sign in again,
  re-enter headers and encryption passwords, and re-trust any self-signed
  certificate. Existing headers on this phone are encrypted automatically on
  first use.
- **Budgets from an older Actual.** Opening a budget last uploaded by an older
  Actual version now applies Actual's missing database migrations, as Actual
  itself would. If the upgrade fails it is rolled back and the budget opens as
  before.
- **Closing accounts.** Closing an account with no transactions now deletes
  it, like Actual. Closing an account with a balance asks you to move the
  balance to another account (recorded as a "Closing account" transfer dated
  today), or to force close, which deletes the account and its transactions.
  Linked bank sync is unlinked when an account is closed.
- **Sync errors that stop retrying.** A sync reset in Actual, a device clock
  that is too far off, or a budget that can't be decrypted now shows a message
  explaining what to do in Manage → Connection & Data, and background sync
  stops retrying until you fix it. Actua never replaces or deletes the local
  budget on its own, so unsynced edits stay on the device. After a sync reset
  in Actual, back up the local budget in Actua before downloading it again,
  because edits that never reached the server aren't in the new copy.

## Changed

- Custom HTTP header values are now stored encrypted and are no longer copied when moving to a new device ([#706](https://github.com/azimul-kabir/actua/pull/706))
- The Add Credit Card picker now lists credit accounts first ([#687](https://github.com/azimul-kabir/actua/pull/687))
- Tapping a credit card payment reminder now opens that card's account ([#685](https://github.com/azimul-kabir/actua/pull/685))

## Compatibility and safety

- Bank link/unlink now writes Actual's `banks` row referenced by `accounts.bank` instead of the non-Actual `accounts.gocardless_requisition_id` column; messages already sent by 1.0.0–1.2.0 stay in the server's sync log and need the recovery above ([#721](https://github.com/azimul-kabir/actua/pull/721))
- Budgets from an older Actual get every missing upstream migration in id order in one transaction, rolled back on failure; Actua-private migration ids are no longer recorded, and older recorded ones are removed, so `__migrations__` and backups match Actual ([#720](https://github.com/azimul-kabir/actua/pull/720), [#726](https://github.com/azimul-kabir/actua/pull/726))
- Writer clocks now advance past the local message log before each send, and the full-sync loop follows Actual's `_fullSync` limit ([#732](https://github.com/azimul-kabir/actua/pull/732), [#733](https://github.com/azimul-kabir/actua/pull/733))
- Selecting a budget already on the device opens the local copy and queues a sync instead of replacing it with the server snapshot ([#703](https://github.com/azimul-kabir/actua/pull/703))
- An expired session forgets only the token; downloaded budgets, encryption keys and unsynced changes are kept ([#704](https://github.com/azimul-kabir/actua/pull/704))
- Custom header values are encrypted with the session token's Keystore key; existing plaintext values are migrated on first read ([#706](https://github.com/azimul-kabir/actua/pull/706))
- Closing an account applies all of its changes in one CRDT batch; unlike Actual, it does not delete an unused GoCardless requisition on the server, and the closing transfer skips transaction rules ([#729](https://github.com/azimul-kabir/actua/pull/729))
- No sync protocol, encryption or Merkle changes; wire compatibility is covered by the new sync parity audit ([#694](https://github.com/azimul-kabir/actua/pull/694))

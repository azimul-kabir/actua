# Actua 1.5.0

Actua 1.5.0 adds an experimental Enable Banking bank sync for European banks,
lets you merge two transactions, search transactions by amount or date, choose
the day your Home summary period starts, and optionally color Budgeted amounts by
category status, with a new "Funded past goal" status. It also makes hand-entered
and duplicated transactions match Actual more closely.

## Before you update

- **Enable Banking is experimental and off by default.** Turn it on under
  Settings → Experimental. It needs an Actual server with Enable Banking
  available, an Enable Banking application whose allowed redirect URL is
  `<your Actual server>/enablebanking/auth_callback`, and it has not been tested
  against a live Enable Banking application yet. With the switch off, Bank Sync and
  accounts already linked to Enable Banking behave exactly as in 1.4.1.
- **Imported-payee rules no longer match hand-entered transactions.** New
  transactions you type in Actua no longer store the payee as the imported payee,
  as in Actual, so a rule with an imported-payee condition only matches bank-sync
  and file imports. Existing transactions are not changed.
- **Duplicates are saved uncleared.** Duplicating a cleared transaction adds an
  uncleared, unreconciled copy, so your cleared balance no longer changes.
- **Overfunded goal categories look different.** A category with a goal whose
  balance is above the goal now shows a new "Funded past goal" status color
  (customizable in Settings → Budget → Category status colors) instead of "Goal
  reached" or its ordinary status.
- As always, let Actua finish syncing before you update, and keep an
  independent backup from Actual before using a new version with a real budget.

## Added

- Experimental Enable Banking bank sync for European banks, switched on under Settings → Experimental ([#833](https://github.com/azimul-kabir/actua/pull/833))
- Optional status-colored Budgeted amounts on Budget rows, and a customizable "Funded past goal" status for categories above their goal ([#831](https://github.com/azimul-kabir/actua/pull/831))
- Choose the day your Home Income, Spent and Net summary period starts, for pay cycles that don't begin on the 1st ([#830](https://github.com/azimul-kabir/actua/pull/830))
- Transaction search now matches amounts and dates typed in the budget's date format, like Actual ([#829](https://github.com/azimul-kabir/actua/pull/829))
- Merge two selected transactions, such as a bank import and the same purchase entered by hand ([#822](https://github.com/azimul-kabir/actua/pull/822))

## Fixed

- Duplicated transactions are now uncleared, like Actual, instead of keeping the original's cleared state ([#828](https://github.com/azimul-kabir/actua/pull/828))
- Hand-entered transactions no longer record their payee as the imported payee, so imported-payee rules and the Imported payee column match Actual ([#827](https://github.com/azimul-kabir/actua/pull/827))
- Categories with a cover-schedule or save-by-date automation plus a spending automation now show spending progress instead of a full goal bar ([#820](https://github.com/azimul-kabir/actua/pull/820))

## Compatibility and safety

- Enable Banking follows Actual's `enableBanking` flag: the Application ID and private key go to your server's `/enablebanking/configure` and are not kept on the device, the bank's consent page opens in the browser, and a link writes the same `accounts`/`banks` fields Actual writes (one `banks` row per account). It does not yet cover business (non-personal) accounts, Actual's per-account "import pending" option, or starting-balance handling ([#833](https://github.com/azimul-kabir/actua/pull/833), [BACKEND_PARITY.md](https://github.com/azimul-kabir/actua/blob/main/BACKEND_PARITY.md))
- The Experimental switch is stored on the device only and is never synced ([#833](https://github.com/azimul-kabir/actua/pull/833))
- A new hand-entered transaction or split parent no longer writes an `imported_description` message; bank-sync and file imports still record it ([#827](https://github.com/azimul-kabir/actua/pull/827))
- Duplicates are written with `cleared` and `reconciled` off, including split children and both transfer legs; the schedule link is still dropped, which is recorded as a divergence in the [transactions parity audit](https://github.com/azimul-kabir/actua/blob/main/docs/TRANSACTIONS_PARITY.md) ([#828](https://github.com/azimul-kabir/actua/pull/828))
- Search reads a typed amount in integer cents (`42.50` is exact; `42` matches 42.00–42.99) and a date in the budget's synced `dateFormat`; the whole-number and day-month rules follow the original request and have not been checked against Actual's source ([#829](https://github.com/azimul-kabir/actua/pull/829))
- The Home summary period is a device-local, per-budget display preference; it never changes budget months or stored data, and the default (day 1) is unchanged ([#830](https://github.com/azimul-kabir/actua/pull/830))
- Status colors and the Funded past goal status are presentation-only; stored budget amounts are unchanged ([#831](https://github.com/azimul-kabir/actua/pull/831))
- No database schema, encryption, Merkle or sync-protocol changes

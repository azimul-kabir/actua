# Actua 1.0.0-beta.27

Beta 27 redesigns Budget Automation as a full-page editor matching upstream
Actual Budget's real automation types, replaces category reordering with a
full Manage Categories page, and fixes long-term target progress and
schedule-link editing.

## Changed

- Redesigned Budget Automation as a dedicated full-page editor matching upstream Actual Budget's mobile structure: a separate "Automations" list (the 7 real contribution types — Fixed amount, Cover schedule, Save by date, % of income, From history, Refill to cap, Whatever is left) and "Options" section (Balance cap, Long-term goal), each capped at one per category. The previous taxonomy (MONTHLY_SPENDING, MONTHLY_SAVINGS, WEEKLY_SPENDING, AVERAGE, COPY, and a REFILL that carried its own amount) didn't match Actual's real model; Refill to cap no longer carries its own amount and instead ties to the sibling Balance cap automation, as it does upstream. Fixed amount gained a day/week/month/year period, Save by date gained repeat/early-spending options, Cover schedule gained a savings mode, and every automation gained a note field
- Replaced the flattened Reorder Categories screen with a full YNAB-style Manage Categories page (create/rename/hide groups and categories, delete a category, move a category to another group) and a separate Reorder Groups screen for group-only ordering. Category drag no longer persists a database/CRDT write on every row boundary crossed mid-gesture — it now only mutates local state during the drag and persists once on drop (reverting on failure), starts immediately from a large handle instead of waiting for a long-press, and auto-scrolls near the list edges; category drag is constrained to its own group, with moving between groups now an explicit "Move to group" action
- Tapping Ready to Budget / To Budget now opens the Budget Summary sheet already expanded in its "Move to Category" state instead of the collapsed action-selection state that needed a second tap; Hold for Next Month and Reset Hold remain fully reachable as before
- Restyled the Plan-view "Ready to Budget" overview card from a 28dp to a 14dp corner radius to match the other cards in that view

## Fixed

- Fixed budget progress bars ignoring "Have amount by a date" and "% of income"/goal-based (`BY_DATE`/`GOAL`) targets until an unrelated whole-budget "Apply Templates" run synced the goal amount from the server; the category model now falls back to computing the goal locally from the target definition so progress reflects it immediately
- Fixed the target editor excluding "Cover schedule" targets from its type picker entirely, and silently dropping `scheduleId`/`scheduleName` when saving an existing schedule-linked target; added a schedule picker to select, change, or clear the link, and fixed the details card to show the linked schedule's name/amount instead of $0.00

## Compatibility and safety

- The automation type rework changes how automations are stored and displayed but was verified against the actualbudget/actual source and Actual's `goal-template.ts`/`category-template-context.ts` reference behavior; `BudgetTemplatePlanner`'s fund-allocation math and all model/UI tests were updated to match
- The Manage Categories redesign does not change category, group, or budget data semantics — only how reordering and editing are performed and persisted
- The long-term target progress fix is read-path only: it changes how the progress bar computes its fraction, not any stored budget or goal value

# Actua 1.4.1

Actua 1.4.1 is a small fix release. Transactions now save to the account and
category you picked when names repeat, reconciled transactions are guarded like
they are in Actual, split lines no longer create "Transfer: …" payees or pick
up the transaction's payee when you only edit the lines, and Budget balance
pills use strong color only when a category is overspent.

## Before you update

- **Transfers on split lines aren't offered.** The split-line payee picker no
  longer lists `Transfer: …` entries, since Actua can't create a transfer from a
  split line yet. A payee you already have with that name still works.
- **Reconciled transactions ask first.** Saving or deleting a reconciled
  transaction, or a transfer whose other side is reconciled, now asks you to
  confirm, and the editor shows a locked Reconciled toggle instead of Cleared.
- As always, let Actua finish syncing before you update, and keep an
  independent backup from Actual before using a new version with a real budget.

## Changed

- Budget balances now only use strong color when overspent, Overspent is a clearer red, zero balances are neutral, and Fully spent defaults to the Partially spent color ([#808](https://github.com/azimul-kabir/actua/pull/808))
- The category status color picker offers more colors ([#808](https://github.com/azimul-kabir/actua/pull/808))

## Fixed

- Transactions now save to the account and category you picked when names repeat across accounts or category groups ([#811](https://github.com/azimul-kabir/actua/pull/811))
- Choosing a transfer on a split line no longer creates a payee named "Transfer: …" ([#812](https://github.com/azimul-kabir/actua/pull/812))
- Reconciled transactions now stay cleared, ask before being edited or deleted, and are unreconciled when moved to another account ([#813](https://github.com/azimul-kabir/actua/pull/813))
- Editing only a split's lines no longer fills lines that have no payee with the transaction's payee ([#814](https://github.com/azimul-kabir/actua/pull/814))

## Compatibility and safety

- Saves and bulk Categorize/Move resolve the account, transfer account and category by id while it still matches the picked name, as Actual's pickers do, instead of by display name ([#811](https://github.com/azimul-kabir/actua/pull/811))
- A reconciled row is always written cleared, and moving one to another account writes `reconciled = 0`, as Actual's desktop transaction table does; confirmations use Actual's `confirm-transaction-edit` texts ([#813](https://github.com/azimul-kabir/actua/pull/813))
- A split child with no payee keeps none unless the parent itself changes, matching loot-core `updateTransaction`/`makeChild` ([#814](https://github.com/azimul-kabir/actua/pull/814))
- The form service refuses a `Transfer:` label on a split line before anything is written; transfer split lines remain unsupported and are listed in [BACKEND_PARITY.md](https://github.com/azimul-kabir/actua/blob/main/BACKEND_PARITY.md) ([#812](https://github.com/azimul-kabir/actua/pull/812))
- The [transactions parity audit](https://github.com/azimul-kabir/actua/blob/main/docs/TRANSACTIONS_PARITY.md) now records these four as matching Actual (or, for split-line transfers, as refused)
- Balance colors are presentation-only; stored budget amounts are unchanged
- No database schema, sync protocol, encryption or Merkle changes

# Server connection, authentication and budget-file parity

This is a feature-by-feature audit of how Actua talks to `actual-server`: server checks, login, the
budget file list, download/upload/delete, and the local budget lifecycle. It is tracked in
[#660](https://github.com/azimul-kabir/actua/issues/660), part of
[#658](https://github.com/azimul-kabir/actua/issues/658). `/sync/sync` itself and its error reasons
are covered in [SYNC_PARITY.md](SYNC_PARITY.md). Archive/schema validation and backups belong to
[#661](https://github.com/azimul-kabir/actua/issues/661), and bank-sync endpoints to
[#673](https://github.com/azimul-kabir/actua/issues/673).

- **Upstream reference:** `actualbudget/actual` at
  [`59fe126f`](https://github.com/actualbudget/actual/tree/59fe126f637d858c061e1eeedbef5436c8f2225a).
  `U/` below is shorthand for
  `https://github.com/actualbudget/actual/blob/59fe126f637d858c061e1eeedbef5436c8f2225a/`. `S/` is
  `U/packages/sync-server/src/` and `L/` is `U/packages/loot-core/src/server/`.
- **Actua paths** are relative to `app/src/main/java/com/azimulkabir/actua/`. `src/test` and
  `src/androidTest` mean `app/src/{test,androidTest}/java/com/azimulkabir/actua/`.
- **Status:** **Match** means the server sees the same request and the same local result.
  **Intentional** means a deliberate Android difference that doesn't change what the server or
  other clients see. **Divergence** means it is filed as an issue. **N/A** means an upstream feature
  Actua doesn't offer (the UI doesn't present it).

## 6. Error mapping for the endpoints above

`/sync/sync` reasons are in [SYNC_PARITY.md §8](SYNC_PARITY.md#8-server-and-sync-error-handling).
The shared helpers `checkAuthorization` and `requireSuccess` (`ActualServerClient.kt:521-529`)
turn 401/403 into `Unauthorized`, turn any other non-200 into `Http(status, body)`, and let
`IOException` through as a network failure. Nothing is written locally until a request succeeds.

| Reason | Where | Actua behavior | Data safety | Target |
| --- | --- | --- | --- | --- |
| Network failure | Any | Message shown (the fallback URL is tried first); local budgets unchanged | No local change | Match |
| `unauthorized` + `token-not-found` / `token-expired` (401) | Any authenticated route | `SessionExpired`: the token is forgotten and the user is asked to sign in again | Local budgets and unsent changes kept | Match ([#698](https://github.com/azimul-kabir/actua/issues/698)) |
| `file-access-not-allowed` (403) | download, info, key, delete | `FileAccessDenied`, with an owner/admin explanation (delete has its own message); other 403s stay `Unauthorized` | No local change | Match ([#701](https://github.com/azimul-kabir/actua/issues/701)) |
| `file-not-found` (400) | download and info → `FileNotFound`; delete → treated as already deleted | Download: message, nothing installed. Delete: continues with local removal after the user confirms. | No local change on download | Match |
| `file-has-reset` / `file-has-new-key` (400) | upload (Actua uploads only new files, so it never sees them); sync | See SYNC_PARITY §8 | – | [#692](https://github.com/azimul-kabir/actua/issues/692) |
| `file-needs-upload` / `file-old-version` / `file-key-mismatch` (400) | sync only | See SYNC_PARITY §8 | – | [#692](https://github.com/azimul-kabir/actua/issues/692) |
| `invalid-password`, `too-many-requests` (429), un-bootstrapped server | login | `LoginRejected` with a readable message | No local change | Match ([#701](https://github.com/azimul-kabir/actua/issues/701)) |
| Decrypt failure / key changed | download | `EncryptionKeyChanged` (stored key removed) or `InvalidEncryptionMetadata`; nothing installed | No local change | Match |
| Invalid or unsafe archive | download | `BudgetFileException`; staging deleted; the live budget is untouched (#661) | No local change | Match |

## 7. Credentials and logging

- **The session token** is AES-256-GCM encrypted with a non-exportable Android Keystore key
  (`actua_server_token`) before it is stored in SharedPreferences (`data/security/CredentialStore.kt:40-63`).
  Budget encryption keys are wrapped the same way (`data/security/BudgetEncryptionKeyStore.kt`).
  `android:allowBackup="false"`, and a transferred ciphertext can't be decrypted on another device.
  The token is sent only in `X-ACTUAL-TOKEN` or a JSON body, never in a URL. The OpenID callback
  token is read from the loopback request and never logged.
- **Custom header values** are stored as plaintext JSON, and `data_extraction_rules.xml` doesn't
  exclude them from device-to-device transfer: [#700](https://github.com/azimul-kabir/actua/issues/700).
- **Logging:** `app/src/main` has only three `Log.e` calls (`data/ActuaRepository.kt:142,154,163`),
  and they log exception class names only. No token, password, header value, key or server
  response body is logged. `ActualServerException.Http` puts the server's response body in its
  message, and that message can appear in the UI and the sync status store. Actual's error bodies
  are reason codes, not credentials.
